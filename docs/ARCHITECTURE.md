# Архитектура приложения

## Принцип

Приложение разделено на UI и транспорт. Экран не формирует BLE-пакеты напрямую.

UI -> useCrawlerController -> CrawlerTransport -> Mock/BLE -> Контроллер

Это позволяет:
1. разрабатывать интерфейс без физического кроулера;
2. тестировать сценарии состояний;
3. заменить mock на BLE после утверждения протокола;
4. не смешивать безопасность UI с безопасностью Контроллера.

## Критичные правила из ТЗ

- Ручное движение инициируется только пока оператор удерживает кнопку.
- STOP доступен отдельно и визуально выделен.
- Недоступные команды блокируются в UI по текущему подтверждённому состоянию.
- UI не считает команду фактически выполненной до подтверждения Контроллера.
- Разрешение экспозиции никогда не определяется только мобильным приложением.
- Реакции на датчики выполняет Контроллер.
